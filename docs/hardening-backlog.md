# Hardening backlog

Findings from verification runs that are deferred to Phase 9 (Hardening) or an earlier phase where noted. Each entry says where it was found and what a fix looks like.

| ID | Finding | Found in | Proposed fix | Target |

| HB-01 | The API listens on `0.0.0.0:3001`, so any container on the `egress` network (for example SearXNG) can reach it directly. Session auth still applies and forwarded client IPs are ignored without the proxy secret, so the exposure is limited. | Phase 1 Docker verification | Bind the API to the `backend` network address only, or require the proxy secret on every API request that does not come from loopback. Done: the API refuses (403) any request that neither carries the proxy secret nor comes from loopback, unless `NCB_API_PROXY_ONLY=false` or no secret is set; the health route stays open. Binding to the `backend` address was rejected because Compose cannot know it in advance. Tests: `tests/integration/server/hardening.test.ts`. The offline test client now sends the secret. | **Done (Phase 9, wave 1)** |
| HB-02 | `web` could reach the internet on Docker Desktop for Mac even though the `frontend` network disables IP masquerading. Expected to hold on Linux but unverified. | Phase 1 Docker verification | Verify on a Linux host; if egress works there too, move `web` to internal networks only and publish through a dedicated ingress network. Open: needs a Linux host. Phase 9 wave 1 tried on Docker Desktop for Mac and learned nothing: the Docker VM itself had no route to the internet then (image pulls failed), so `web` failing to reach `https://example.com` proves nothing about the masquerade setting. | **Open** |
| HB-03 | A fresh `pnpm install` tries to compile `better-sqlite3` with node-gyp because the package has a `binding.gyp`; the Dockerfiles use `--ignore-scripts` and install the prebuilt binary separately. | Phase 1 Docker build | Document in the development guide; consider `onlyBuiltDependencies` / prebuild install so local installs never need a compiler. Done: `better-sqlite3` removed from `onlyBuiltDependencies` and added to `ignoredBuiltDependencies`, so `pnpm install` uses the shipped prebuilt binary and needs no compiler (checked with a clean offline install). `@openzim/libzim` legitimately needs python3, make and a C++ compiler; documented in `docs/guides/development.md` and the README. | **Done (Phase 9, wave 1)** |
| HB-04 | Crawl `maxDuration` deadline uses the wall clock, so a clock jump (Pi without RTC) can end a crawl early. | Phase 3 crawl engine | Measure elapsed time with `steadyClock` from `@ncb/shared`, like leases. Done: `CrawlService` wraps its clock in `steadyClock`, so deadlines, pause and resume ignore wall-clock jumps (test: `tests/integration/storage/crawl-limits.test.ts`). A restart re-anchors the clock, as it does for leases. | **Done (Phase 6)** |
| HB-05 | robots.txt and the first page request run inside one claimed job, so they are not spaced; assets within a page are not spaced individually (`assetConcurrency` 1 only). | Phase 3 crawl engine | Route robots and asset fetches through the per-host politeness gate, or document the bounded burst. Done: `HostPacer` (`apps/server/src/limits/pacer.ts`) spaces robots.txt, the page request (in the `beforeHop` hook, after the robots check, so each redirect hop too) by the host's `crawl_delay_ms`, and files by `min(delay, 250 ms)`. Files are not spaced by the full delay because a page can have a hundred on its own host; the bound is four a second per host. Hosts with no delay row are not slowed, and neither is a single page a person saved by hand (an explicit one-off request must not wait on a delay a crawl left on the host; the e2e storage spec caught that). Tests: `apps/server/test/hardening.test.ts`, `tests/integration/server/hardening.test.ts`. | **Done (Phase 9, wave 1)** |
| HB-06 | `maxBytes` can overshoot by roughly one page. | Phase 3 crawl engine | Reserve the per-document cap against the remaining budget before fetching. Done: each page reserves its share of what is left of `maxBytes` (minus pages in flight) before it is fetched; the document cap and the asset cap are cut to it, `bytesFetched` counts the page's real size once, and a document that does not fit ends the crawl with `max_bytes` (same test file; the old `maxBytes` assertion now says `<=`). | **Done (Phase 6)** |
| HB-07 | The renderer forward proxy listens on all interfaces inside `server`, so `web` and `searxng` can reach it.
